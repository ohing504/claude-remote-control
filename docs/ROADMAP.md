# crc 로드맵

구현 순서와 진행 상태. 설계 근거는 [`ARCHITECTURE.md`](ARCHITECTURE.md).

각 마일스톤은 기능 묶음 + **통과 검증 기준**을 함께 둔다. 검증은 "될 것 같다"가 아니라 신선한 실행 증거로만 체크한다.

## 진행

- [ ] **M0 · 스캐폴드** — `go mod` 초기화, config 로드/저장(`workspaces.json`).
  - 검증: `crc ls` 빈 목록 → `crc add` 후 목록에 반영.
- [ ] **M1 · 등록 CRUD** — `add`/`rm`/`ls`, 중복·경로 유효성 검증.
  - 검증: 잘못된 경로·중복 이름 거부, 정상 등록·삭제 반영.
- [ ] **M2 · 생명주기 (핵심)** — `up`/`down`/`status`, env 절대 규칙 주입.
  - 검증: **띄운 서버의 spawn 자식에서 폰으로 `SendUserFile` 파일이 실제 도착하는 것으로만 통과.** "환경변수 넣었으니 되겠지"는 불가.
- [ ] **M3 · 로그·포그라운드** — `log`(tail -f), `fg`(현재 터미널 연결).
  - 검증: 서버가 dead일 때 원인이 로그에서 보인다.
- [ ] **M4 · TUI** — 상태판·토글·로그뷰(bubbletea).
  - 검증: 리스트에서 상태 색이 실제 프로세스 상태와 일치, enter 토글 동작.
- [ ] **M5 · CLAUDE.md 스캔 등록** — `scan`으로 후보 디렉토리 수집·등록.
  - 검증: root 아래 CLAUDE.md 있는 디렉토리만 후보로, `.git`·`node_modules` 스킵.
- [ ] **M6 · 다듬기·설치** — 상태색·업타임·dead 정리, `go build`로 `~/.local/bin/crc` 설치.
  - 검증: 설치된 바이너리로 전체 흐름 재현.
